Can you put a language model in charge of an NPC?

A look at the games trying it, the cost of running it, and what happened when I let agents playtest mine.

Today

  1. What an LLM-controlled NPC costs
  2. What studios have shipped
  3. Design exercise: choose your AI
  4. What I learned from agent playtesting

Sam Gilson · Game2Learn Lab · NC State · Guest lecture for Dr. Tiffany Barnes. Use ← / → to change slides. Animations have playback controls and step lists. Press N for speaker notes.

I gave the September lecture on using AI to build games. Today I want to look at something different: letting the model make decisions inside a game. We will look at real examples, sketch a couple of designs, and finish with playtesting work from my own games. The class exercise is the middle of the talk.
background from our last lecture

This time, the model controls what happens in the game

September: building the game

  • We used models to write code, prototype mechanics, and make assets.
  • The output becomes part of the build.

Today: running the game

  • An LLM decides what an NPC says, plans, or tries to do.
  • Or we give the model the controller and ask it to find bugs.
  • An agent reads game state and chooses an action. That decision can come from a behaviour tree, a learned decision tree, or an LLM.
  • The design question: what does an LLM give us that a smaller game AI system cannot?
Tie this to the September lecture. Generating a script is one problem. Letting a model choose what an NPC does while somebody plays is another. Use the course definition of an agent: observe, decide, act. Behaviour trees, learned trees and language models are competing ways to make that decision.
sourced start with one conversation

One NPC reply takes more than a prompt

Send to the model

  • Character profile and speaking style.
  • Current game state and the NPC’s knowledge.
  • Conversation history.
  • The player’s latest question.

Cost estimate: assume 1,000 input tokens.

Get back

  • About 100 new output tokens.
  • A reply checked against game rules and safety limits.
  • A response before the player gets tired of waiting.
  • A character prompt can produce good dialogue. It can also forget earlier conversations or offer a quest that the game has no way to run.
  • Each new reply needs another call. That matters once thousands of players start talking.

Gallotta et al., Large Language Models and Games: A Survey and Roadmap, IEEE Transactions on Games, 2024.

Build the request with the class: persona, world state, history, the player’s line. Then ask what has to happen after the model replies. The survey documents lost context and invented quests. On the next slide, keep this one reply in mind and multiply it across a live game.

    sourced keeping a character consistent

    The character you prompt may change over time

    After eight rounds

    In a chatbot-to-chatbot study, the models started drifting from their instructions within eight exchanges.

    Long conversations

    A seven-model study found weaker persona consistency as dialogue continued, especially in goal-driven tasks.

    Smallville

    In Smallville, Isabella gradually adopted other characters’ interests instead of holding her original goals.

    Model size is no guarantee

    PersonaGym found that a larger, more complex model did not necessarily follow a persona better.

    • Designers need to know what the character will do on the hundredth conversation. LLM characters need memory management and checks to stay in bounds.

    Li et al., Measuring and Controlling Instruction (In)Stability in Language Model Dialogs, COLM 2024. de Araujo et al., Persistent Personas?, EACL 2026. Park et al., Generative Agents, UIST 2023, §7.2. Samuel et al., PersonaGym, EMNLP Findings 2025.

    Consistency is a design requirement, especially when players can repeat an encounter. The Smallville example is a good one: an NPC gradually picks up other characters’ interests. A model can make a character feel spontaneous, but the studio still has to keep that character recognisable across long conversations.

    sourced case study · what we can verify

    Where Winds Meet: how much can its NPCs change?

    What we know

    • Steam discloses live AI NPC text and voice dialogue. That disclosure appeared 28 days after launch.
    • Some side NPCs can chat. Their conversations affect a small set of outcomes, such as friendship, hostility or a weekly gift.
    • Players have talked NPCs into marking conversational tasks as complete.
    • The studio has not published the model, hosting setup or moderation system.

    What I wanted to know

    • My first guess was that the studio prewrites or caches most replies.
    • I could not verify that. Player guides show the same line producing different replies, so a fixed answer cache seems unlikely to explain everything.
    • Shared context or popular replies could still be cached.
    • What is clear: the NPC can talk freely, but the game restricts which state changes its dialogue can cause.

    Steam store page, read 2026-11-18; disclosure date from Arcanum RPGs, 26 Sep 2026, comparing Wayback snapshots. AllThings.How, 22 Nov 2025. Kotaku, Dec 2025. Non-determinism: Space4Games, 27 Nov 2025.

    Here is a game the room might recognise. I assumed the studio would cache lots of responses, but I could not confirm that from public material. Guides show replies changing across attempts. The stronger finding is about game-state control: the dialogue can be open-ended while the outcomes stay limited. Ask what goes wrong when players can talk a model into completing a quest.
    proposed architecture animation

    A cache can answer before the model runs

    Exact-match caching that also gives every player the same answer: Infinite Craft, as reported by Wikipedia, citing PC Gamer (4 Feb 2024) and the New York Times (4 Mar 2024). Semantic caching and its false positives: GPTCache, RedisVL SemanticCache. Prefix caching: Anthropic prompt caching. Batch at half price: Claude pricing, read 2026-11-18.

    Run Hit, then Miss, then Warm the cache. There are three separate tricks here. Exact-match caches reuse a tested answer. Semantic caches also reuse answers for similar questions, with some risk of mismatches. Provider prefix caches reduce the cost of repeatedly sending the persona, but the answer still has to be generated. Ask how many of the NPC’s common questions you could answer before you ever call a live model.
    sourced the rest of the NPC system

    The harness decides what the model can do

    Keep the cost down

    • Cap reply length. For the larger model in our estimate, output tokens dominate the bill.
    • Summarise old turns. Four exchanges can mean 4,900 input tokens, not 4,000.
    • Try a smaller model first. RouteLLM reported 35–85% lower cost at roughly 95% of GPT-4 quality.

    Handle a crowd

    • Rate limits matter. Twenty million replies an hour is about 5,600 requests every second.
    • Queue requests or use a written fallback when demand spikes.
    • Do offline work in cheaper batches. Players cannot wait for a batch job.

    Keep control in the game

    • Check the player’s input and the NPC’s reply.
    • Translate model output into a small set of valid game actions.
    • In PUBG Ally, a behaviour tree handles fast actions while the model makes higher-level choices.

    Ong et al., RouteLLM, ICLR 2025. OpenAI rate limits and moderation, read 2026-11-18. NVIDIA, How Krafton built PUBG Ally, 25 Jun 2026. History arithmetic from the estimate on the cost slide (each exchange adds about 150 tokens). Hejmadi (Arm), Augmenting NPCs with LLMs: Practical Experience from NC State University & Arm, GDC 2026.

    This is the system you actually have to ship. It decides what state the model sees, what actions it can request, how much compute it gets and what happens when it fails. There was a GDC 2026 talk from Arm and NC State about on-device NPCs and mapping model output to game actions. That is a useful local example.
    sourced research prototypes

    Smallville made the idea convincing, and expensive

    Smallville (Generative Agents)

    • 25 agents lived in a simulated town, using memory, reflection and planning.
    • One agent planned a Valentine’s party. Twelve heard about it; five attended.
    • Two simulated days took days to run and cost thousands of dollars in model calls.

    Voyager (Minecraft)

    • An LLM writes Minecraft skills as code, tests them and saves them.
    • Later tasks use the saved skills without regenerating them.

    Let the model write the AI

    • PORTAL generates behaviour trees across thousands of shooter games. Those trees control play.
    • In LLM-BRAIn, observers distinguished generated robot trees from human-made ones in 4.53 out of 10 trials.

    Park et al., Generative Agents: Interactive Simulacra of Human Behavior, UIST 2023, §7.1 and §8.2. Wang et al., Voyager, 2023. Xu et al., Agents Play Thousands of 3D Video Games (PORTAL), 2025. Lykov and Tsetserukou, LLM-BRAIn, 2023.

    Smallville is the model for the life sim we will discuss in the activity. The Valentine’s party was a memorable example of agents coordinating without a fixed script. It also took days of processing and substantial token cost for two game days. Voyager and PORTAL take another route: generate reusable code or trees, then execute those in the game.
    activity studio exercise

    Your team is pitching the AI for one of these games

    Cul-de-sac

    • A 20-hour, single-player neighbourhood sim.
    • You share a street with 12 neighbours. They remember your actions, gossip and follow daily routines.
    • The hook: players come back to see how the neighbourhood has changed.
    • Team of six. No budget for per-player inference.

    Night Shift

    • Eight museum levels built around patrols and line of sight.
    • Guards investigate noises and call for backup when something looks wrong.
    • Designers tune patrol routes and sight cones for predictable difficulty.
    • Speedrunners repeat the same encounters hundreds of times.
    Both games are invented for this exercise. Read the two briefs, then ask pairs to pick one. Cul-de-sac leaves room for social improvisation. Night Shift gives the design team a reason to demand precise, repeatable guard behaviour. Let the class discover that trade-off themselves.
    activity pairs · 4 minutes

    Where would you put an LLM in your game?

    Your task: add generative AI to Cul-de-sac or Night Shift. Which NPC or system does the model power? What does it read, what does it output, and when does it run: live during play, or while the game is being built?

    Four minutes. Then we will hear a few designs.

    Give pairs four minutes. The task is to add an LLM or another generative model to one of the two games, somewhere it does real work. Ask for a specific NPC or system, a specific input and a specific output. Take two or three designs and put them on the board. Try to hear one from each game so the trade-offs are different.
    activity design review

    What can the model do that a behaviour tree can’t?

    Name one thing your design gets from generative AI that a behaviour tree, a dialogue tree or hand-written content could not give it. What would the player see or hear that was impossible before? Is that worth the cost?

    Push for the affordances that are new: open-ended replies to anything the player types, content no one authored line by line, reading free text or speech, improvising inside a persona. Ask what the player sees or hears, rather than accepting general claims about more intelligent NPCs. If the answer is something a tree could already do, ask what the model adds. The next slides give you follow-up questions to choose from. Use whichever ones challenge the designs the class proposed.
    follow-up design review

    Could a behaviour tree handle this?

    A behaviour tree is cheap, readable and easy to tune. Which part of your character actually needs a language model?

    • Halo 2 used roughly 50 authored AI behaviours. The design emphasised readable intentions and control for designers.
    • "It may not be the behavior we want for the game experience." (Dave Mark, on machine-learned behaviour)

    Isla, Handling Complexity in the Halo 2 AI, GDC 2005. Graft, When artificial intelligence in video games becomes… artificially intelligent, Game Developer, 22 Sep 2015.

    Start here if a group put a language model behind the guards in Night Shift. A player needs to learn the guards’ patterns, and the designer needs to tune them. Halo 2 is the classic reference for readable and designer-controlled behaviour. Keep the question tied to gameplay: what can the model do that warrants the extra system?
    follow-up design review

    Could you learn this behaviour from players?

    If the goal is to copy a player, try a learned decision tree. What does an LLM add beyond a model trained on the player’s actions?

    • Forza’s Drivatar learns driving patterns, with designer limits on aggression and collisions.
    • Killer Instinct’s Shadows reproduce a player’s combos and mistakes for offline matches. Microsoft has not disclosed the algorithm.

    Thompson, How Forza's Drivatar actually works, Game Developer, 1 Jun 2021. Xbox Wire, Fear Your Shadow in Killer Instinct, 29 May 2015. Decision-tree learning: Millington and Funge, Artificial Intelligence for Games, 2nd ed., 2009, ch. 7.

    Connect this to decision-tree learning from class. If the proposed character imitates a player’s fighting or movement, a smaller learned policy might be enough. Forza and Killer Instinct demonstrate the design goal. Avoid claiming that either game specifically uses a decision tree unless that implementation is documented.
    follow-up design review

    Does the model have to run during play?

    Generate dialogue before release and keep the useful lines. What would you cache? When does a live call earn its cost?

    • An answer already in the cache needs no fresh inference. Only unfamiliar questions reach the model.
    Press on any design that wants unlimited live conversation. Which questions will players actually ask? Could the team generate and review replies during development? Use the cache animation again if needed. A live model earns its place when the unexpected questions matter to the game.
    follow-up design review

    Now ship it to 10,000 players

    Where does inference run? Estimate concurrent calls. Set a cost limit, a content check and a fallback for slow or failed requests.

    Make the group name the hardware or service. Cul-de-sac has no per-player server budget, so they must choose local inference or offline generation. For Night Shift, latency during a guard encounter is especially hard to justify. Ask what the player sees when the model does not respond.

        my proposal with a large studio's budget

        With unlimited resources: an agent behind every NPC

        What the player can do

        • Pick a preset option for ordinary dialogue and game actions, such as opening the shop.
        • Use a Talk command to say anything to the NPC.

        What guides the agent

        • Every NPC is a generative AI agent running in a harness.
        • Each NPC has a persona.
        • A behaviour tree guides what the agent outputs.

        What the harness lets it do

        • Create a new quest, and a new item as its reward.
        • Add new items to a shop.
        • Grant the player an ability, curse the player, or open a bounty on them.
        If I were a game designer at a company the size of Blizzard, with unlimited resources, this is what I would try. Every NPC is a generative AI agent in a harness. Players still get preset options for ordinary dialogue and actions like opening the shop, and a Talk command lets them speak to the NPC in their own words. The persona and the behaviour tree guide what the agent outputs. The harness gives the agent actions that change the world: new quests, new reward items, shop stock, abilities, curses and bounties.
        my proposal two sample encounters

        Let players create quests, then distil them into decision trees

        The old lady

        • Her persona believes her daughter is missing.
        • Talk to her the right way and the agent creates a quest to find the daughter, who she is convinced is dead in a cave. You find a corpse there; reporting back completes the quest.
        • Keep talking and she may ask about her daughter’s features. Describe them wrongly and she may become convinced her daughter is alive, and create a new quest.

        The nobleman

        • You sprint into him, and he challenges you to a duel for your honour.
        • Refuse and he puts a bounty on you.
        • Accept and the agent creates two quests, one for each outcome. Kill him and you are thrown out of town, and the harness sets you to wanted there. Let him flee and you gain honour in the town for silencing a bully.
        No designer wrote these two encounters line by line. The agent produced them from a persona, a behaviour tree and the harness’s actions. In the background, a system built on decision trees caches the interactions and quest lines each player creates in their own single-player instance and saves them to a server. After the agent mode has run for about a month and there is enough data, every agent is converted into a learned decision tree trained on what players induced during the playtest. The game gets the model’s spontaneity for emergent world design, then ships fixed, small models that are not generative, to save cost. Connect this to decision-tree learning from class.
        sourced testing the game

        Give the model a controller and a test build

        • During development, varied play styles can expose bugs that scripted tests never encounter. That is where I have found model agents useful.
        • Researchers used simulated player personas for testing long before LLMs. Holmgård and colleagues studied this in 2014.

        EA SEED, 2020

        RL agents found an exploit involving missing collision and all five places where the test character could get stuck.

        TITAN, 2025

        Agent tests in two MMORPGs completed 95% of tasks and found four new bugs. They also produced 30% false alarms.

        MIMIC, 2025

        Seven player profiles improved coverage. Each action averaged about $0.05 and 12.4 seconds.

        GBQA, 2026

        Across 30 games, the strongest model found 48.39% of 124 verified bugs.

        Holmgård et al., Generative Agents for Player Decision Modeling in Games, FDG 2014. Bergdahl et al., Augmenting Automated Game Testing with Deep Reinforcement Learning, CoG 2020. Wang et al., TITAN, 2025. Chen et al., MIMIC, ASE 2025. Jiang et al., GBQA, 2026.

        Here the model is useful for a different reason. A testing agent can try unusual routes through a game, and a strange choice may reveal a defect. The research is promising but imperfect: TITAN reported false positives, and GBQA did not recover every bug. I have not found direct evidence that randomness alone improves bug yield, so I present that as an observation from my own work.
        my work two real playtests

        My agent found a bug in its own controls

        From my survey of 30 test subagents in games built with Builder, October to November 2026: Agents as Playtesters (Builder, sgilson7/builder-setting). Long Time Comin' playtest, 10 Oct 2026; Floodline playtest, M10.

        Long Time Comin’ is a real-time game, but the model cannot aim and dodge at frame rate. My harness therefore replays a command log into a deterministic core and returns the screen as text. The agent noticed that shots missed at long range and traced the problem to the harness using chest position instead of the camera line. In Floodline, the harness cropped out every refusal message. Both examples show why the testing interface needs testing too.
        my work how I run them

        How I set up an agent playtest

        Setup

        • Give the agent a readable game view: text harness or browser controls.
        • Give it the player manual. Hide source code and balance values.
        • Assign a play style. Chaos, timing and odd-input testers make different choices.
        • Separate observations from guesses about the cause.
        • Reproduce the bug yourself, then add a regression test.

        What went wrong

        • My harness missed refusal messages, aimed incorrectly and once reported a comparison after running zero ticks.
        • Agents play differently from people. Mine aimed better but dodged worse.
        • 30 agent runs consumed 4.46 million tokens; median 140,000 per agent.
        • Agent reports can point to defects. I still need human players to study difficulty, enjoyment and usability.

        Agents as Playtesters, compiled 2026-11-11 from my Claude Code sessions (2026-10-10 to 2026-11-08) and the projects' playtest notes. A classroom app in the survey is counted but not described.

        This is my working setup from the Builder projects. The important thing is to let the agent play from the player’s point of view. Different personas help it choose different actions. Every finding needs reproduction. And an agent is not a human research participant: I use these tests for software defects, then ask people what the game feels like.
        for your own projects

        Choose the smallest system that delivers the behaviour

        • For live NPC dialogue, budget per reply and put firm limits on what the model can change.
        • Store answers you can test in advance. Reserve live calls for questions you could not anticipate.
        • Use a model when varied dialogue or planning improves the game. Consider generating the behaviour before launch.
        • Use behaviour trees or learned policies when you need fast, repeatable decisions.
        • For testing, try agents with different play styles. Reproduce their bug reports before making changes.
        End on the design choice. Pick the smallest system that produces the experience you want. You can still use a language model during development, even when none runs in the finished game. Ask the class where they would spend their own compute budget. Then take questions.
